# Phase 1 — Global Account/Auth Layer

## Design

Create one new file, `account.js` (project root), that owns the entire auth lifecycle, and slim `chat/auth.js` down to credentials + sign-in UI. Chat becomes a consumer of the global `Account` service. One auth listener total, explicit session restore, no UI changes, no schema changes, no key changes.

### 1. NEW: `account.js` — global `Account` singleton

Loaded in `index.html` right after `chat/supabaseClient.js` and before `chat/auth.js`. Depends on `window.sb` (runtime) and `Profiles` (runtime, resolved after all scripts finish executing since every await resumes post-script-load).

- **State**: `Account.user`, `Account.profile`, `Account.ready` (a promise resolving once with `{user, profile}` — or `{user: null, profile: null}` when logged out — usable by future modules via `await Account.ready`).
- **`Account.init()`** (idempotent, self-invoked at script load):
  1. Explicit session restore: `const { data } = await sb.auth.getSession()` → set `user` (requirement #2; supabase-js still rehydrates the session from its `sb-…-auth-token` localStorage key, so existing persistence is untouched).
  2. If a user exists, load/ensure the profile (below).
  3. Subscribe to `sb.auth.onAuthStateChange` **once**, skipping the `INITIAL_SESSION` event (already handled by the explicit restore — this preserves the old single-notification behavior and avoids the double-fire race that `auth.js`'s header comment warns about). `SIGNED_OUT`/`USER_UPDATED`/`SIGNED_IN`/`TOKEN_REFRESHED` flow through the same handler.
  4. Resolve `Account.ready` and mark initial delivery done.
- **`_setUser(user)`**: sets user; if user exists, loads `Profiles.getById(user.id)`; if missing, attempts the existing fallback (`user.user_metadata?.username` → `Profiles.createProfile`, wrapped in try/catch so a failure — e.g. taken username — leaves profile null and falls through to the modal, exactly as chat.js does today). Sets `profile`; notifies listeners with `(user, profile)`.
- **`Account.onAuthStateChange(cb)`**: registers a listener, returns an unsubscribe function. **Late-subscriber replay**: if the initial state has already been delivered, invoke `cb` once (deferred) with the current `(user, profile)`. Guarantees exactly one initial callback per listener regardless of whether a module subscribes before or after the restore completes — this is what makes the service safe for future Games/Watch/Music/AI/Settings modules.
- **`Account.signOut()`**: `await sb.auth.signOut()`; the resulting `SIGNED_OUT` event drives state clearing (`user = null`, `profile = null`) and listener notification — single source of truth.
- **`Account.setProfile(profile)`**: updates `Account.profile` and notifies listeners (used after profile creation via the modal and after profile edits).

### 2. `chat/auth.js` — lifecycle removed, credentials/UI preserved

- Remove: `currentUser`, `_onChange`, `init(onChange)` (the `onAuthStateChange` subscription moves to account.js; this keeps exactly one listener in the codebase).
- Keep unchanged: `usernameToEmail`, `signUp`, `signIn` (username-only auth preserved verbatim), `renderAuthScreen` (UI untouched).
- Remove `signOut()` (Chat switches to `Account.signOut()`); update the header comment to reflect that lifecycle now lives in Account.

### 3. `chat/chat.js` — consume the global layer

- `Chat.init`: replace `await Auth.init((user) => this.handleAuthChange(user));` with `Account.onAuthStateChange((user, profile) => this.handleAuthChange(user, profile));`
- `handleAuthChange(user, profile)`: now receives the already-loaded profile.
  - `!user` → existing teardown + `Auth.renderAuthScreen(...)` — unchanged.
  - `user && profile` → `startChat(user, profile)` — unchanged.
  - `user && !profile` → the rare fallback: render the existing `Profiles.renderUsernameSetup` modal (same UI, same overlay); in its `onDone`, add `Account.setProfile(createdProfile)` before `startChat` + the existing `location.reload()`. The internal `Profiles.getById` + user_metadata creation block is deleted from chat.js (now Account's job — still one creation path, no race).
- `renderUserBar`: sign-out button → `Account.signOut()`.
- `onProfileUpdated(updated)`: add `Account.setProfile(updated)` so the global layer stays fresh after profile edits (one line).

### 4. `index.html` — one script tag

`<script src="account.js"></script>` between `chat/supabaseClient.js` and `chat/auth.js`.

No other files touched: Games/Watch/Music/AI/Settings/dev modules, profiles schema, CSS, and both API keys remain untouched.
